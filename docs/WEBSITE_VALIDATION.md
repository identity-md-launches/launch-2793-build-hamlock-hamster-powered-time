# HAMLOCK website validation

Complete for the stated website scope. This is the contributor's local evidence, not an independent audit or network certification. No deployment, publication or real wallet transaction was performed.

## Scope and assumptions

One English page, static export at root `dist/`, site label `hamlock`. Source is under `web/`; the existing Solidity source, tests, build settings and dependencies remain intact. The production export was served under `/preview/`, exercising relative asset paths at a gateway-style subpath.

The visual idea is a dark green dot-matrix instrument panel for a time lock powered by a pixel hamster. The lock form precedes the illustration on phones. No fake jar, balance, live counter or leaderboard entries ship. The active-night estimate (about 10km), 0.878-metre wheel calibration, chain ID, deployment address and deployment block are explicit task inputs. Contract numerical rules are read through public getters. Missing data remains unknown.

Publishing/IPFS pinning is after this handoff. The final hostname is not supplied; sharing uses the visitor's current page URL. Open-in wallet links similarly preserve the current path.

## Commands and evidence

Executed from the repository using the frontend npm prefix:

```sh
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web run validate
npm --prefix web run verify:live -- --out artifacts/live-verification.json
node .imd/reads/skills/design-critic/scripts/taste.mjs --out test/scratch/taste
```

The browser commands used an externally installed browser cache; the taste probe was given the local Playwright module via `IMD_PLAYWRIGHT`. No browser/cache/dependency archives are in the submission. The supplied managed browser tool failed initialization with `EROFS` while opening its cache. Local Playwright successfully inspected the actual export instead.

WebKit initially lacked system libraries and an EGL software renderer. Required Ubuntu libraries were downloaded and extracted outside the repository, with software EGL enabled for validation. Browser host preflight was bypassed after library setup; actual WebKit rendering, interactions and screenshot creation then succeeded. This is not a claim that the original host had WebKit support without that setup.

The production build emits one upstream warning that `node:worker_threads`, imported by an `ox` Tempo module, is externalized for browser compatibility. No script errors or missing local resources were observed on the exported EVM interface in the tested states. Coinbase's SDK is a separate lazy chunk.

The pinned ABI was generated by Foundry using Solidity 0.8.28. Source matched commit `9681bafe1674f448285c0599a2dbec90e95da4eb` byte-for-byte. Canonical ABI Keccak:

```text

```

Compiled runtime, with the verified immutable SqueekCore address inserted at Solidity's immutable references, exactly matched live Sepolia code. Runtime Keccak:

```text
0x2a7d8020300f3be9fb399174fcd6059fdaefbff70b715574937a76d77b6303aa
```

The live snapshot at Sepolia block 12036309 returned settled work 58518, no active jars, no locked principal and no Opened events since block 12036187. The API returned `IDLE`, rpmMilli 0 and cumulative work 58518. These are dated observations, not application defaults. The UI fetches current values on every visit.

## Useful interactions exercised

The validation harness serves the production export with test-only RPC/API responses and generated mock wallet addresses. It never signs or broadcasts a real transaction. It also performs a separately identified live read-only smoke check.

- EIP-6963 MetaMask/Rabby discovery, generic-provider suppression, missing-extension guidance, local Coinbase SDK loading, rejection recovery, keyboard activation, Tab boundaries, Escape and focus return.
- Phone wallet rows for MetaMask, Coinbase, Rabby and Phantom; correctly encoded current-page URLs and Coinbase Smart Wallet row. A physical app handoff was not performed.
- Wrong-chain transaction blocking, `wallet_switchEthereumChain`, and unknown-chain `wallet_addEthereumChain` with Sepolia parameters.
- Amount minimum/maximum, negative/scientific notation rejection, sub-wei precision rejection, field error association and focus, and slider-to-work-unit math.
- `lock` simulation and wallet request with correct contract, selected km and exact value; successful receipt, refreshed jar and exact prefilled X text/current-page URL.
- All eight requested custom errors translated into English before funds are sent.
- Jar-relative settled progress and strictly supplementary live overlay; rpmMilli conversion; pending reward and unavailable/stale telemetry.
- Break cancellation, wei-exact refund/penalty/reward, `breakJar` confirmation and receipt; changed rewards require a second confirmation.
- `open` after deadline while core reads fail and API is down; break is unavailable for an openable jar.
- RPC failover, total outage with unknown values and retry recovery; 15-second telemetry polling and removal of a previously live overlay after failure.
- Leaderboard event start block, exclusion of deadline-only completions, contract score reads, km/jar tie ordering, and paper-hands values.
- Reflow at 320, 390, 680, 800 and 1440px, independent 200% text enlargement, and reduced motion.
- axe WCAG 2 A/AA, 2.1 AA and 2.2 AA rules on the disconnected page, wallet dialog, active jar and break dialog: no violations.
- WebKit at 390px: subpath assets, wallet connection against the mock provider, primary form validation, no overflow or script errors.

The Chromium first-screen test measured the Lock ETH button fully within the 844px viewport. Font loading was verified with `document.fonts`, and the visible Doto lettering and Geist copy were inspected in screenshots.

## Remaining limitations

No real extension transaction/signature, Coinbase account/passkey creation, physical phone/wallet deep-link handoff, screen-reader session, native browser zoom or forced-colors visual inspection was performed. The mock provider is deliberately a test environment and cannot certify a particular wallet app/version. Short-chain reorg behavior and transaction cancellation/replacement paths were reviewed in source but not exercised against live transactions. Public endpoints can be slow, unavailable, rate-limited or reject old log ranges; errors are visible and retryable. The initial event scan grows with contract history and depends on public RPC log support.

The static export needs JavaScript and a browser with native dialog, BigInt and modern fetch/AbortSignal support. The noscript notice explains that requirement. A shared relative og:image is intentional until the hosting plane supplies the final URL; gateway/social-crawler behavior is outside this local check. No claim of an independent security review is made.

Design guide attribution and licenses are retained in `DESIGN.md` and `docs/DESIGN_GUIDANCE_LICENSES.txt`; local font and wallet-mark notices are included with their assets.
